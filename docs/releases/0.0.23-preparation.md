# 0.0.23 release preparation

This candidate incorporates the accepted UX fixes, restored SAP AI Core code,
provider identity and transport repairs, persistence/cancellation hardening,
bounded long-task history, and verified Agent continuation/count reporting.
The current UI layout is retained.

Publication is not part of this preparation. No remote branch update, version
tag, GitHub Release, or community-plugin publication is authorized here.
The main-branch workflow can publish a new version after its real gate succeeds;
keep this preparation on its local `codex/release-prep-0.0.23` branch.

## Reproducible candidate

1. Commit all candidate source and test changes, excluding generated state,
   credentials, unrelated artwork, reports and PDFs.
2. Run lint, both type checks and the development build required by project rules.
3. Run `npm run build:production` from that exact commit.
4. Set real `E2E_TEST_PROVIDER`, `E2E_TEST_API_KEY`, `E2E_TEST_MODEL` and
   `E2E_TEST_BASE_URL` in the process environment, then run
   `npm run verify:release:real`.

The runner freezes the three release assets and checks the build's source-input
hashes and commit. Every real Obsidian case verifies the installed hashes. Fresh
JUnit files, persisted conversations, screenshots, actual tool journals and
generated note contents belong to one run ID. Old, skipped, failed, partial and
artifact-mismatched evidence cannot satisfy the gate. The final report is
generated from these artifacts; preflight runs are explicitly excluded.

## Mandatory live cases

- Real chat response and actual token usage.
- Real Agent source-file read confirmed from successful action records.
- Four correctly named notes with the required content and index links.
- One continuous long task: at least 20 minutes, all 60 notes (by default), each
  at least 1,200 independently counted words, plus every index link. Completion
  and every artifact are required; the earlier 60-percent acceptance is removed.

The long run retains the original duration requirement. A task finishing early
cannot earn a duration pass by waiting after completion. Workload settings and
actual duration are recorded in the run manifest and product evidence.

## Scope and evidence

Use service-default reasoning: no thinking or reasoning-effort overrides. This
preparation uses the real Manifold custom-provider route. Ollama remains excluded;
SAP AI Core is included as code but receives no live tenant call. Neither excluded
provider is described as live-verified. No mock service is used in the release
gate; release diagnostics do not query the deterministic CI server.

Generated evidence is under `tests/e2e/reports/real-release/` or the explicitly
configured run folder. The human-readable English preparation report is under
`test-results/release-prep-0.0.23-2026-11-05/report-en.html`. These generated files
are excluded from source commits and scanned before packaging. The version bump
synchronizes package, manifest, lockfile and compatibility metadata.
