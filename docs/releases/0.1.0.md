## Publication through the existing CI/CD workflow

The authoritative publisher is [`.github/workflows/ci-cd.yml`](../../.github/workflows/ci-cd.yml). After the user explicitly requested temporary removal of real-verification, a normal main/master push starts `check` → `build` → `release`. It reads the version from manifest.json, skips publication if that version's tag already exists, runs Lint/type checks and one production build, checks the downloaded file hashes, and automatically creates the version tag and Release pinned to that workflow's source commit. No new real-gate pass is claimed. Do not pre-create the tag or manually create the Release to bypass this chain.

The Release receives `main.js`, `styles.css` and `manifest.json`. The workflow separately retains the installation ZIP and build hashes/provenance as Actions artifacts, and creates artifact attestations. No fresh real-test diagnostic artifact is produced while that job is removed. Local preparation reports and prior certificates retain their original scope and are not attached as new release-test results.

The repeated local 0.1.0 run was stopped at the user's request after chat, Agent read and linked-note cases passed; its long task was interrupted. It is not a full-gate pass. No further local full run is part of this update. The previous CI/CD attempt failed its real-service credential check; it remains a failed run. The temporary job removal is an explicit publication decision, not a successful rerun of that gate.

Earlier preparation commits used `[skip ci]`; the current instruction supersedes that approach. The push omits CI skip markers. Only the publisher's real-verification task/dependency is removed; build and release safeguards remain. The independent E2E and Verification Gate workflows include mocks and are unchanged. GitHub-managed CodeQL and Dependabot workflows also remain enabled. Ollama and live SAP calls remain outside the current live preparation scope.

To restore the real-verification job from Git history, configure `E2E_TEST_PROVIDER`, `E2E_TEST_MODEL` and `E2E_TEST_API_KEY`, plus `E2E_TEST_BASE_URL` where appropriate. The service must be reachable from the GitHub-hosted runner; a tester's localhost address is not a remote service URL. These credentials are not required by the reduced publisher. A source push alone still does not establish successful publication: its remaining mandatory jobs must succeed and the Release must exist.

## Exclusions and known limits

- Ollama is implemented but excluded from this current live acceptance. SAP AI Core code is restored without a live tenant call. Other provider names in the UI are not independent live certifications.
- The earlier Qwant keyless route returned 403; provider availability/credentials still apply.
- Completion/count guards have bounded recognized fields/phrases. They do not prove arbitrary arithmetic, all languages, model reasoning quality or every semantic task.
- Stop/Continue retains bounded evidence, not automatic crash replay or exactly-once external writes. CLI/MCP/HTTP processes are not sandboxed by the built-in write-proposal UI.
- Mock-based unit/CI/mutation suites were not executed during the earlier no-mock local preparation. The subsequent request to run normal CI enables the existing independent workflows; their actual results must be read from Actions. Skipped checks are not passing checks.
